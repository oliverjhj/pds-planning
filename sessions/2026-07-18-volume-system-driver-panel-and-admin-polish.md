# Session: 2026-07-18 — Volume system rebuild, driver-panel rework, admin polish, kiosk launch fix

**What changed:** Phase 2 items 1–3 shipped, plus a latent compliance defect found and fixed, a Defer-Without-Guilt item superseded by a built feature, and a kiosk dual-instance bug diagnosed and closed. All on `pds-android`; eleven commits, all owner-glass-verified and pushed.

1. **Volume system rebuilt on diagnosed reality (Phase 2 item 1).** On-device diagnosis (temp `PDS.VolDiag` logging + `dumpsys audio`) proved two things: **Android silently drops app writes to `STREAM_ACCESSIBILITY`** (no exception — only enabled accessibility services may write it), so the driver slider, the hardware-key clamp, AND the announcement-time floor raise had never actually worked; and **the a11y stream is platform-aliased (index-rescaled) to `STREAM_MUSIC`** — announcement loudness IS media volume. Owner decisions: remove the slider (redundant), then remove the entire key interception (native Android volume keys + system panel everywhere — the desired UX; also fixes the dialog-vs-app inconsistency), keep ONLY the announcement-time floor raise, retargeted at `STREAM_MUSIC` — making the Reg 13 floor real on glass for the first time (verified: media volume 0 → announcement plays at the 30% floor). `DriverVolumeController` deleted; `VolumeFloorMath.clampedStreamIndex` deleted (tests trimmed, ceil-rounding guard kept); admin PIN-owned floor setting unchanged as the raise's knob. **Two recorded FR-AT-44 divergences** (slider clause; button-interception clause) — docs-are-evidence, owner-decided.
2. **Driver panel fixed four-row grid (Phase 2 item 2).** Previous|Next, H&R start|end, diversion pair, Jump-to-stop|Trigger-announcement, then End Journey. The diversion pair mirrors the H&R pair's persistent presentation: left cell relabels in place (start ↔ "Diversion active — update stops", START/EDIT selector), End cell always present, `enabled = diversionActive`. `DriverPanelButton` gained an `enabled` param with a faded-solid disabled treatment (palette-only, no border — Rule 20 idiom preserved).
3. **Trigger-announcement menu built — supersedes FR-AT-41 repeat-last** (owner-redesigned; the retained-last-holder blocker is moot). `TriggerAnnouncementOverlay` in the JumpToStopOverlay slot/posture (above panel, below regulated overlays, collapse-on-fire). Two row contracts: **informational rows (route + per-stop next-stop) are ANNOUNCE-ONLY** via the new `AnnounceOnDemandUseCase` (bare `AnnouncementBus` emit — no index write, no `journey_events` row, no transient visual; hero/tube-map stay the state-bound carrier); **regulated rows (H&R start/end, diversion start/end) reuse the panel buttons' state-coupled use cases** (one behaviour, two entry points; diversion end disabled while inactive). **Termination deliberately absent** (End Journey is its only trigger). Row previews show the literal announcement text; route/stop previews mirror the render worker's exact composition ("This is the {number} to {name}" / "Next stop: {name}").
4. **App-wide button width/outline pass (Phase 2 item 3).** New `presentation/common/StandardControlWidth` (280 dp, one tuning point) applied to every admin takeover (both PIN screens, menu, deregister confirm, volume/timeout editors, event log — buttons AND entry fields), all driver-overlay bottom buttons (Jump/Trigger Done, stop-selector Cancel/Start/Done), calibration, journey-end, and Start Journey (centred, FR-AT-28 hints centre-aligned). Secondary actions converted `TextButton` → `OutlinedButton` with the **default grey outline** (owner-picked over ink — matches the six pre-existing outlined menu rows, so **no new Steelglass idiom and no three-way design sync**). Long admin body copy capped at `AdminBodyTextMaxWidth` (420 dp, centred) after the deregister warning read as an edge-to-edge banner.
5. **Kiosk dual-instance race fixed.** Owner repro: first launch after a rebuild → calibration exit landed on the route list with no admin menu and the theme/gear cluster missing; relaunch cleared it. Diagnosis: `MainActivity` had no `launchMode` (standard) while registering LAUNCHER+HOME, so an AS deploy could stack a second instance; both activity-scoped `AdminPinViewModel`s subscribed to the process-singleton `AdminNavigationSignal`, and the wrong instance could consume (acknowledge-and-clear) the calibration-exit reopen flag, leaving the visible instance stuck on `AdminStep.Calibrating` (which also hides the cluster). Fix: `android:launchMode="singleTask"` (correct HOME/kiosk posture; protects every singleton-signal ↔ activity-VM pair) + the reopen collector consumes only while its own step is `Calibrating` (instance-safe, defence-in-depth). Single-instance confirmed via `dumpsys activity` at the exact post-deploy moment that previously raced.
6. **Calibration screen polish.** Top app bar (and its dead band) removed → inline title, wizard content mid-screen, pinned bottom "Back to admin menu" `OutlinedButton` (admin idiom; same exit semantics — BackHandler/Done unchanged, FR-AT-49 round-trip intact). Card-match rectangle spawns at 0.3 fraction (was 0.7 — slider/button started below the fold; 0.3 ≈ true card width on the 13″ target).
