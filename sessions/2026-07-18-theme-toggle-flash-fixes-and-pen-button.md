# Session: 2026-07-18 — Theme-toggle flash fixes (both surfaces) + pen floating button

**What changed:** Fixed the theme-toggle "container flashes out of time" artefact on both surfaces — same symptom, two entirely different causes. **Dashboard:** the glass panels' `backdrop-filter` re-samples a `background-attachment: fixed` body background a frame late in Chromium, so every glass panel (routes table, login card, device tables) visibly lagged the theme flip; the Steelglass canvas gradient now lives on a `body::before` fixed underlay (visually identical, seam-free under scroll, `bg-background` stays the worst-case anchor on body) which composites on the fast path and flips in the same frame. Pushed and verified live on `pds-dashboard.com` (deployment `dpl_7FJtrzz…` READY, new `body:before` rules confirmed in the served CSS, old `background-attachment` gone — no webhook miss this time). **Android:** diagnosed on the Lenovo by frame-stepping an adb screenrecord of the toggle — the sync strip, route cards, and canvas all flip in ONE frame, while the M3 `TopAppBar` fades ~20→245 brightness over ~190 ms afterwards: Material3 runs the app-bar container colour through an internal `animateColorAsState` (meant for the scroll-elevation tint), so a theme change gets spring-animated instead of snapping. Fix: both `TopAppBar`s (route list + route detail) now use explicit **transparent** container + scrolledContainer colours — theme-invariant, so nothing animates, and it aligns the bars with the Steelglass posture (their Scaffolds were already transparent over the app-root canvas; the opaque default was quietly painting a flat band over the gradient). Also: the **Lenovo pen floating button** is now hidden on the dev tablet system-wide (`settings put secure pen_set_show_button 0` — owner-decided; revert with `… 1` or the Lenovo pen settings toggle).

**Decisions made:**
- **Pen floating button: system-wide off, no app machinery** (owner-decided). A per-app hide would need `WRITE_SECURE_SETTINGS` granted per device via adb plus writes to ZUI-private setting keys — fragile across firmware, no-op on other hardware, and on a deployed kiosk the app is always foreground so per-app ≡ system-wide anyway. Rejected.
- **Transparent, theme-invariant TopAppBars are the idiom** for Material screens over the Steelglass canvas — starves M3's internal app-bar colour animation of any colour change AND stops the bar over-painting the canvas gradient.
