**Decisions made:**
- **One Sentry project per surface** (`android`/`dashboard`/`edge-functions`), staging vs production split by the `environment` tag — supersedes the frozen Data-Arch six-DSN plan; follows the Android implementation precedent (owner-approved). Sample rates 0 everywhere (errors and crashes only, protecting the 5k/month free tier).
- **Environment derived from the SUPABASE_URL project ref** in `_shared/sentry.ts` (staging/prod ref map + `SENTRY_ENVIRONMENT` override) — no per-project environment secret to mis-set after a project reset.
- **Scrub hex threshold is 40, never 32** — Sentry protocol IDs are exactly 32 hex; ≥32 makes ingest silently reject every event (verified empirically; pinned by regression test).

- **Deploy flags must match deployed shape:** `generate-pairing-code` and `enqueue-render-job` are `verify_jwt: true`; the other six deploy with `--no-verify-jwt`. Blanket-flag deploys would silently change auth posture (deployed-shape audit catch).
